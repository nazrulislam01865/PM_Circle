# Achievements & Learning Record

Member route: `/dashboard/features/achievements`. Existing member shell, authentication and profile privacy remain in place. Four views, 42 prototype definitions, medal artwork, status/search/category filters, badge detail progression, pathways and recorded activity use the shared achievement components and centralized Inter design system. Dashboard and member profile reuse the latest earned medals.

The member projection reads verified activity using one bounded windowed union and, on the full achievement page, one pathway aggregate. Profile completion uses the existing service. No new migration, AI call, per-card query or client-side production award mutation. Course completion is evidenced by issued course certificates; learning minutes use completed PMP practice duration (capped per attempt); profile threshold timestamps are not invented. Records show up to 30 recent rows per supported activity source. Badges are derived from current qualifying records, not immutable award history; removal or moderation of source records may affect them. Features without verified activity sources (including placeholder project and Scrum simulators) remain locked, with an explanation in badge details. Real pathways use the published database catalog rather than sample counts. Sample activities are isolated in browser memory and reset on reload; they never grant real badges. Profile preview is a tab within achievements, separate from the actual existing member profile.
