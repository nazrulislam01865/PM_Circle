# AI Resume Assistant — current draft exports and sticky right rail

## Root cause
The existing live/full preview uses the local `data` and `cv` editor state, but the export links used GET `/settings/profile/resume/export`, which only reads the previously submitted profile. Word output was an HTML document with a `.doc` extension; Microsoft Word could discard CSS variables, heading alignment, and contact separators.

## Changes
- Full preview remains the same reusable React A4 component and opens at its beginning. Returning to the editor restores its prior scroll position.
- Print / Save as PDF and Download Word résumé send the current reviewed editor snapshot to POST `/dashboard/resume-assistant/export`; no save, profile mutation, draft session write, AI request or additional database query for the document is performed. The existing GET route still exports saved profile data for the Resume & imports tab.
- Existing member/verified middleware and assistant entitlement are retained. The endpoint validates the complete document, limits it to 150 KB, and has an independent ten-requests-per-minute member limiter. The browser handles failures inline and prevents concurrent exports.
- Shared `ResumeExport` service renders the supplied template's section order and detail lines for both PDF and genuine editable `.docx`. Word uses native OpenXML paragraphs, styles, bullets, tables, A4 margins, contact separators and dated page-number footers. PHP's existing `ZipArchive` extension packages the result; temporary files are removed in `finally`. No package dependency or migration is introduced. Source Sans Pro is requested, with sans-serif fallback when unavailable. Actual page breaks may vary with font availability and print engine. PDF export remains the browser's print/save-to-PDF workflow.
- The existing right column contains the Save draft and Submit profile actions, quality card, full preview action and A4 preview. It sticks below the shared header/profile tabs at desktop workspace widths, with independent preview-column scrolling. On narrow or short screens, the right column remains in normal document flow. Application controls use existing design tokens; document typography remains separate.

## Verification
- Native OpenXML parts generated by the PHP service, parsed as XML, packed into a DOCX fixture, and rendered with LibreOffice: three pages visually inspected, all nine populated sections, contact separators, bullet content and page numbers present. PHP CLI here lacks ZipArchive, so PHP HTTP response ZIP packaging was not executed end-to-end (fixture packaging used Python solely for testing).
- Offline Chromium component fixture at 1440, 1024, 768 and 390 px: no horizontal workspace overflow; sticky right actions verified at the two wide sizes; narrow sizes stacked normally. Not a running Laravel/Inertia application.
- Targeted Node tests: 11/11. Full regression suite: 393/394; existing unrelated Exam Simulator `AI Tokens` heading assertion fails. PHP syntax and changed TypeScript transpilation syntax checked. Laravel feature tests added for entitlement, current unsaved export content, escaping and non-persistence; not run because vendor dependencies/PHP extensions are unavailable. Production build blocked by Node 22.16.0 (project requires 22.18+) and unavailable npm cache package `yuku-parser`.

## Deployment
Retain the existing `.env`, database and storage. No migration is required for this change. Ensure `php -m` reports `zip` (install `php8.4-zip` on PHP 8.4 if missing). Use Node 22.18+ and run `npm ci`, `npm run types:check`, `npm run build`, `php artisan optimize:clear`. Run `php artisan test --filter=ResumeAssistantBuilderTest` against the test database. Check a real uploaded/extracted résumé with unsaved edits before and after export, and open the Word file in Microsoft Word.
