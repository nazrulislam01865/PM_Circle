# AI Workspace operation diagnostics — Archive 10

## Root cause
The workspace tested most generation keys with GET /v1/models, while feature settings used actual Responses generation and the configured moderation policy. A key restricted to Responses can legitimately reject the model-list endpoint. The previous AUTH_OR_SCOPE_DENIED conflated invalid credentials and permission errors. Active described routing assignment, not successful authentication. A custom pool label did not change the internal routing target.

## Changes
- `AiCredentialDiagnostic` tests the supplied secret, using OpenAI Responses, Omni Moderations, Gemini generateContent or Anthropic Messages at fixed provider endpoints. Generation uses a short synthetic prompt, bounded output, disabled redirects and an approved model and price. It does not create user content or charge member credits. The representative model is selected from the slot's existing configuration (prefer a saved key's assigned enabled feature for the shared OpenAI slot, otherwise PMP explanation or another configured operation). Daily Challenge retains gpt-5-nano.
- `AiDirectUsage` records the diagnostic with the correct provider, reserves global/monthly/feature and applicable credential budget, settles reported usage including failed output validation, and retains reservations for ambiguous outcomes. Explicit rejection releases the reservation. No automatic retry or fallback occurs. Unknown diagnostics block repeated tests for the same accounting reference until reconciled. The existing ledger records costs for environment replacements under `credential:rotation:<slot>` until the new credential has an ID; these costs are in global totals, not attributed to the old working key.
- `AiWorkspaceCredentials` uses operation diagnostics for Test and Rotate. Failed rotations do not replace the stored key. New successful tests use `OPERATION_VERIFIED`; previous `ACCESS_VERIFIED` records do not qualify for new activation/route assignment. Existing active assignments remain intact. Runtime recovery is distinguished from manual verification.
- `AiWorkspaceController`, `AiFeatureRouting` and the workspace UI use safe diagnostic messages and verified status. Route assignment remains managed in the workspace. Activation updates a slot default; explicit feature routes override the default. Review both generation and review routes after switching Daily Challenge.
- `FeatureConnectionStatus` uses the same exact-primary credential test for feed moderation, including budgeted Responses diagnostics and optional moderation preflight. Daily Challenge, PMP and Career Trends keep the full existing generation and policy tests; those are more comprehensive than credential tests. `TrendAiConnection` and `ConnectionControls` link to the correct workspace routing target.
- `AiWorkspace.tsx`, `WorkspaceShared.tsx` and `SettingsShared.tsx` display separate routing and diagnostic status, routing target, human-readable error, and correct test scope. Opening Add API key from a feature's Manage API keys link preselects the intended routing target. No changes to centralized styles.

## Administrator steps
1. In AI Workspace > API Key Management, locate the credential with Routing target: Daily Challenge (not an Interactive credential merely named Daily Challenge).
2. Test the existing environment credential or add/rotate a managed replacement. Approve model pricing and configure spending limits if required. A generation diagnostic is a real, small paid request.
3. Activate the verified managed credential, then open AI Workspace > Feature Configuration. Set both Daily Challenge generation/review to the intended credential, or use the current routing target default. Verify the actual feature connection from Daily Challenge AI settings. Repeat for other features.
4. Do not delete existing environment keys until all migrated routes and required moderation dependencies have been verified. Ordinary assignment changes do not require queue restarts; restart workers on deployment of this code.

## Limitations and verification
No new migration, dependency or feature business logic. Existing provider support and server-configured flags/models remain unchanged. This is a credential diagnostic/routing usability fix, not a complete migration of every legacy AI configuration setting. A representative credential capability check does not certify every model, scope or full workflow; full feature diagnostics still verify the existing feature path. No live provider requests were made here. PHP lint, TSX transpilation and the source regression suite were run. Laravel tests and frontend build require vendor/node_modules, absent in Archive 10. New integration tests cover restricted keys, denied scope, budget denial, unknown outcomes, rotation, activation and provider accounting; run in staging before deployment.
