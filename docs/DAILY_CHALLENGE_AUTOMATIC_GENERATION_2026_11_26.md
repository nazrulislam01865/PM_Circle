# Daily Challenge automatic generation and recovery

## Admin workflow

Open `/admin/ai/daily-challenge` (AI settings > Daily Challenge). Assign the existing Daily Challenge generation operation to an enabled OpenAI credential, check the Post Check moderation credential and budgets, and test the connection. Save enabled Daily Challenge settings to opt into automatic generation and publication. The old editor approval selector is removed; answer evaluation remains independently configurable. Generate Daily Challenge queues a selected date (today or future, with an optional exact title), using the saved generation guidance. It does not overwrite an existing published challenge or successful/in-flight request. The visible Generation status panel shows request status, attempts and safe error codes; old dates are grouped under history. Use Refresh status to retrieve current results.

## Scheduling and safeguards

`ai:prepare-scenarios` runs every 15 minutes and prepares today and tomorrow in Asia/Dhaka. A rejected admission for one date does not stop the other. `daily-challenge:publish` runs every five minutes; only today's valid completed draft may publish once, at or after the configured time and before its expiry. `daily-challenge:expire` closes expired discussions. Automatic publishing still requires the explicit saved enabled/auto-publish policy. The old approval-only command remains available for legacy operations but is no longer scheduled. No past-day backfill. Existing future drafts are retained.

The first three attempts use a 30-minute automatic retry interval; subsequent recovery attempts use a three-hour interval, with a six-attempt ceiling for the regular generation/recovery path. A manual request can bypass the delay but not the ceiling or the terminal-failure checks. The existing separately authorized console recovery procedure remains available for exceptional legacy cases. Retry is allowed only for explicitly retryable terminal errors, with all earlier requests terminal, and never for rejected content or uncertain provider outcomes. Failed request records, cost allocations and audit history are preserved. A missing moderation key is rejected before creating a paid request; actual calls retain input/output moderation and structured-output validation. The pre-existing local-only smoke-test configuration is not a production bypass.

## Deployment

No new migrations or seeders. Preserve `.env` and persistent storage/database. Install dependencies for the target platform and rebuild the frontend. Restart queue workers and verify the Laravel scheduler is running every minute. `PM_AI_ENABLED` and `PM_AI_EDITORIAL_ENABLED` must be true, with valid feature prompt, model price, budgets and configured credentials. `php artisan daily-challenge:check --probe` checks the existing configuration and moderation endpoint; `php artisan schedule:list` lists the schedule. `php artisan ai:prepare-scenarios` submits real generation requests when configured, and `php artisan daily-challenge:publish` processes due validated drafts.
