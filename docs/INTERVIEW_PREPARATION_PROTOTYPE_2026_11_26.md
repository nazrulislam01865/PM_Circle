# Interview Preparation — prototype-aligned workflow (2026-11-26)

## Scope
Based on the supplied `PM_Circle_Interview_Preparation_AI (3).html`, six screenshots, and the current approved Inter design guideline. The existing authenticated member header, sidebar, offer strip, and footer are preserved. All four steps use the same `FlowPage`, `Wizard`, `Brief`, `Intro`, difficulty badges and feedback component. The original embedded prototype hero image is stored as a local JPEG. The global design tokens remain authoritative over the prototype's older Rajdhani/Source Sans typography.

## Workflow
- Target role: active industry, role and experience options; profession grouping derived from active role labels; optional requested experience and JD text, sample JD, and temporary TXT/DOCX/PDF extraction. Recognized JD title, industry and years can update selected active options when continuing. Extracted files are not retained; JD text is used only for selection, not stored in the session table or sent to a provider.
- Question set: recommended, common, and focus-area mixes, active question types, count and answer mode; actual mix preview, generate/rebuild, and start. The existing catalog remains authoritative. The server builds a bounded candidate pool, ranks for scope and keyword relevance, and returns an immutable draft snapshot. Rebuilding may produce a different set when the catalog permits. Sparse catalogs may yield different mix proportions; actual counts are shown. No matching focus questions return validation feedback. Difficulty and topic labels are educational heuristics, not administrator-authored metadata.
- Practice: per-question progress, playback, editable text/dictation, deterministic answer evaluation, previous/skip/next, saved feedback. Skip is stored with score zero; evaluated responses are saved and can be re-evaluated after editing. Existing unfinished sessions remain accessible. Browser speech recognition may send audio to the browser's own service; PM Circle only saves text. The browser must permit microphone access. Unsubmitted edits are held in component memory, not persisted across a full reload.
- Results: aggregate practice score, answered count, duration, expandable review, history (existing latest-30 limit), new session. Existing historical unscored sessions are not retroactively scored.

## Backend and security
- Existing ownership checks, authenticated routes, CSRF, rate limits and row locks preserved. Preview and start are session-locked; drafts are scoped to the member and selection hash, expire after 30 minutes, and are consumed on successful start. A stale draft must be regenerated. The existing direct start endpoint is retained for compatibility. Changes to administrator questions after preview do not alter that snapshot.
- The prototype uses a local heuristic rubric and the existing project's `pm-interview.ai_feedback_enabled` is deliberately false. The new deterministic server-side rubric provides strengths, improvements and a suggested outline; it is not AI, certification or hiring assessment. No artificial demo tokens, provider calls, new queue jobs, or credit deductions. AI Workspace integration is not enabled by this UI update.
- The current active administrator catalog takes precedence over demo choices. Other professions and counts such as 20 require active catalog options and appropriate curated questions. No new options are silently seeded.
- Uploads are validated by type, extension and maximum 5 MB. DOCX uses existing bounded extraction (PHP ZipArchive), PDF uses existing Poppler `pdftotext`; scanned PDF requires pasted text. No external extraction dependency added.
- Existing question sessions, answers and AI usage ledger remain intact. New nullable columns are `profession`, `requested_experience`, and `target_labels` in `interview_sessions`. No destructive migration or seeding.
- The previous history/detail page is replaced by the requested prototype list/review flow. The legacy trend chart, score-category dashboard and live countdown UI are not part of this prototype; estimated session duration remains available and old countdown data is retained for compatibility.
