# Learn & practice: prototype implementation (29 October 2026)

## Scope and source

Source: the two images in `WhatsApp Unknown 2026-10-29 at 2.21.05 PM.zip`, the attached "What is a project?" screenshot, and SRS v1.0 sections 3, 4.5, 4.6, 9.3, 10 and 13. All public, login/signup and existing member dashboard components are preserved. The new feature renders `/learning`, `/learning/{path}`, and `/learning/{path}/modules/{module}/activities/{activity}` through Inertia.

## Implemented

- Learning catalogue layout with tabs, searchable/filterable paths, practice types, progress and achievements display, saved user path access, responsive right rail.
- Learning-path detail, goals, 6-module beginner roadmap, collapsible modules, save/unsave and contextual call to action.
- Four activity views (lesson, MCQ, short answer, mini scenario), breadcrumb, checklist, stepper and nav buttons; first beginner MCQ uses screenshot wording and answers.
- Per-member persistent quiz answers and completion state. Server-only objective keys and explanations before check. Three submitted MCQ responses complete the MCQ activity; incorrect responses are recorded rather than treated as correct.
- Input validation, authenticated + onboarded guards, idempotent unique DB records, rate-limited writes, and private written responses (owner-only projections).
- Local/test-only repeatable demo curriculum for five career levels. No demo users/achievements/subscriptions generated by this learning seeder. The awards panel is a visual illustration; actual awards and AI explanation are not implemented.

## Database and demo setup

Create/configure `.env` (example included). Before testing on a **fresh local or testing database**:

```bash
composer install
npm install
php artisan key:generate
php artisan migrate
php artisan db:seed
npm run build
php artisan serve
```

`DatabaseSeeder` runs `LearningDemoSeeder` only in local/testing, not in production. The seeder may be run again without duplicating paths, modules, activities or questions. Do **not** seed demo content into live customer data. For an existing application, migrations are additive and no destructive production schema operation is required. Do **not** run `migrate:fresh` on existing data.

After signing in and completing onboarding:

- `/learning`
- `/learning/student-beginner`
- `/learning/student-beginner/modules/1/activities/1` (lesson)
- `/learning/student-beginner/modules/1/activities/2` (MCQ)
- `/learning/student-beginner/modules/1/activities/2?question=2` (second question)

## Release limitations

- The UI follows supplied proportions/colours/text, but **pixel-level browser comparison could not be executed** without a browser/runtime and installed dependencies. Screens must still be checked at 1280px and 360px and compared against images.
- Full Laravel/TypeScript tests and production JS build were not runnable in this container: dependencies and PostgreSQL driver are absent. PHP lint and TS syntax/local import checks are recorded separately in `docs/LEARNING_VERIFICATION.md`.
- Only the initial training curriculum is seeded. Real authoring, lesson versioning, exams, formal achievement issuance, AI assistance/credits, adaptive levels, and paid lesson catalog require the separate SRS Phase 2 implementation. Do not present sample achievements as earned or AI summaries as live feedback.
- An imported `public/build` bundle was removed because it did not include the new pages. Rebuild in the target environment before serving the website.
- Email verification remains temporarily optional from the preceding revision. Re-enable for production.
