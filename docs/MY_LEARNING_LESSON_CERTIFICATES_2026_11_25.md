# My Learning, lesson and certificates — November 25, 2026

Source: Archive 3(3).zip; PM_Circle_Design_Guidelines (1)(7).html (byte-for-byte equal to the copy in the archive); three user-provided prototype screenshots.

## Implementation

- My Learning is now the enrolled-course list, with all/in-progress/completed filters, three equal desktop columns (two or one in narrower rails), progress, continuation/review, course detail and certificate actions. The original learning paths are still available at `/dashboard/learning?tab=paths`, linked beneath the list to avoid removing the old workflow.
- Certificates are listed with actual course title, issuance date, completed label, view and PDF print action. Certificate records are scoped to the member; no public personal data or example achievements. PDF action opens a print-only browser view (choose Save as PDF); no new PDF package or certificate artwork was requested.
- Lesson workspace is shared across public/member URL families, with the current lesson and side outline, reading/video, real knowledge check when a published question matches the lesson topic, overview, authored takeaway/application/example/references, private notes, AI assistant and Q&A availability states, published course PDF files, and complete/continue. Public visitors see only the safe outline and enrollment link. Existing course detail layout is retained with lesson navigation added.
- No new AI provider, fake AI credits, fabricated answers, learner discussions, ratings, videos or completion data. AI lesson assistance and discussion are not implemented backend features in the archive; UI shows unavailable states. A knowledge check uses the existing course practice bank (not the PMP exam bank), only when practice is enabled and the topic title exactly matches the lesson title. The demo-only “show wrong-answer example” and “preview zero tokens” controls are intentionally omitted. PDF resources use the existing authorized download route; the resource schema is course/section-based, not lesson-specific. Video is optional and configured as a direct HTTPS media URL by an admin; external media is subject to the host's own access controls and browser compatibility. Use only approved media hosts. Existing lesson content is never replaced.
- Admin course editor gains optional fields for video, takeaway, application timing, example, references and applied-learning prompt inside the existing study-note card. No admin redesign. Public course detail reflects whether video is configured, without exposing its URL before enrollment.
- UI uses existing PublicLayout/MemberDashboardLayout, catalog card image structure, central progress and guide buttons/controls, Inter and semantic typography roles. No global token changes. Prototype's display font is not introduced because the supplied guideline specifies Inter and 44px controls.

## Database and security

Run `php artisan migrate` (local) or `php artisan migrate --force` (approved production deployment). One additive migration creates `learning_course_lesson_progress` and `learning_course_certificates`. No reseed or destructive update. Lesson progress and notes are private, scoped by member/course/content key. Stable hashes survive reordering, and changed lesson content is treated as incomplete. Previous earned certificate remains as historical evidence even if the curriculum changes. Completion writes are transactional, unique constraints prevent duplicate progress/certificates, and existing enrollment rows serialize completion for the member/course. Certificate eligibility is completion of every current study lesson, not an exam pass or external professional certification; no prior completions are inferred from enrollment. One certificate per course/member. Existing plan and enrollment checks are reused, and certificates previously earned remain accessible to their owner even after membership downgrade. Writes are independently rate-limited and JSON failures display inline. Notes save explicitly; no writes on typing. No new query is made for public guest learning/certificate lists, and member list uses bounded bulk lookups without N+1. The existing browse catalog queries and card designs are unchanged.
