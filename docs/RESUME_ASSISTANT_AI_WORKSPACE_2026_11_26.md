# AI Resume Assistant / AI Workspace integration

## Existing gap and changes
The original assistant used local extraction only; Resume & imports already resolved a dedicated Workspace credential but used deployment flags/model/limits. Analysis and rewriting were central AI gateway features but required a saved upload. The new implementation adds operation-level model, credential, status, quota and output controls in AI Workspace > Feature Configuration. Editor extraction is opt-in; local extraction remains available. Both extraction paths use the same model and daily request setting. Analysis and rewriting use the existing queued gateway, consent, credit and budget controls, with the current editor draft as an alternative to a saved résumé. Suggestions must be explicitly applied and saved. Existing CV template, export, deterministic completeness score, membership rules and routes are retained.

## Deployment
Back up the database. Apply the source files, preserving environment and storage. Run `composer install`, `php artisan migrate`, `npm ci`, `npm run types:check`, `npm run build`, `php artisan optimize:clear`, `php artisan queue:restart`. Use the Node version supported by the project (Node 22.18+). Restart the existing AI workers (Horizon termination/restart if using Horizon). Verify `public/build/manifest.json`.

## Configure
1. Enable the existing central master switch (`PM_AI_ENABLED=true`) for analysis/rewriting. The extraction feature has its own switch with legacy fallback for existing installs.
2. In AI Workspace > Models, enable an OpenAI model that supports structured responses, publish approved token pricing. Set a sufficient global budget; financial settings require explicit admin permissions.
3. In Feature Configuration configure `resume_extract` with the model, daily request limit, output limit and disabled status until credentials are ready. Add a key in API Key Management with routing target **Resume Extraction**. Test it and activate or explicitly assign it to the feature. This credential requires Responses access. Extraction supports same-model backup keys only.
4. Configure `resume_analyze` and `resume_rewrite` in Feature Configuration, using the OpenAI general routing target and tested credentials (Responses and Moderations access), with credit tariffs, quotas and output limits. Enable the desired operations after confirming prompt and pricing. Existing feature settings are preserved; if missing, migration creates disabled rows with conservative defaults (gpt-4.1-mini, Pro, 1 credit, 3 requests/day, 1500 output tokens) and baseline safety prompts. The model must still be approved. Extraction uses the existing direct usage ledger; it is not a member-credit debit operation. Legacy environment settings remain fallbacks for extraction until saved in Workspace.
5. Verify with a Pro test member. Import a text-based PDF or DOCX, select AI extraction with explicit consent, review fields without auto-saving, and run analysis and section suggestions on the current draft. Check Workspace usage and ensure the queue worker processes AI requests. Test disabled features, invalid credentials, exhausted limits and rejected consent. No live AI requests were run during source verification.

## Limits and privacy
Editor extraction uses a temporary local file and bounded text input (PDF first ten pages, 5 MB, no OCR), sends it only after consent, requests store=false, and returns a reviewable draft without creating a profile résumé. The editor provider call is bounded to 35 seconds after parsing; legacy import still uses its queued extraction. Review and rewrite use the existing encrypted queued AI request/result flow and require member credits/entitlements. The editor review excerpt omits dedicated contact fields but free-text content may still contain personal information; the member must consent. Provider data retention is governed by provider terms. Disable a feature to block new operations; queued analysis/rewrites recheck enabled status before execution. No unrelated features are changed.

## Verification limitations
Source regression and syntax tests were run; actual database migrations, Laravel integration tests, dependency installation, production compilation and real OpenAI requests must be verified on the target installation. The included Laravel tests use a fake provider. Do not run rollback against real draft consents: the migration refuses rollback if those records exist. No destructive reset or reseeding is necessary.
