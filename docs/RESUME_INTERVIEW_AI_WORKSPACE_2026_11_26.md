# Resume Assistant and interview AI review

## Scope
The supplied project already has Workspace routes for resume_extract, resume_analyze and resume_rewrite. They remain intact. The new interview_answer_review operation uses the same central AI gateway, not the disabled legacy interview OpenAI job. Normal interview evaluation and scoring remain rule-based and free of AI credits. A member explicitly requests optional AI coaching for a saved evaluated answer and consents to provider processing. The result contains summary, strengths, improvements and an illustrative response; it does not change the practice score. New review defaults: disabled, Plus/Pro, gpt-5-nano (requires model approval), 1 credit, 10 successful/pending reviews per UTC day, 1800 output tokens, 6000 answer characters. Existing resume plan requirements remain Pro. Workspace supports same-provider primary and backup credentials for these review operations. The minimum plan cannot be lowered below the catalog entitlement by configuration.

## Deployment
Back up the database and preserve the existing .env, APP_KEY and private storage. Install Composer dependencies, run `php artisan optimize:clear`, `php artisan migrate --force` on production, install frontend dependencies (`npm ci`), run `npm run types:check` and `npm run build` using a supported Node version (22.18+), then `php artisan optimize` and `php artisan queue:restart`. Restart supervised workers using the project's actual worker configuration; ensure the `ai-interactive` queue is consumed and the queue retry-after exceeds the 65-second job timeout. If Horizon is actually installed/configured, use its normal termination/restart procedure. This archive does not add Horizon configuration. Do not overwrite the production .env or reset/seeding existing data. Enable `PM_AI_ENABLED=true` in the existing environment and rebuild config cache if it is not already enabled.

## Admin configuration
Go to `/admin/ai/workspace/features` (AI Workspace > Feature Configuration). Enable an approved OpenAI model that supports structured Responses, publish actual current provider prices through existing model pricing controls, and configure positive global AI budget and optional feature/monthly limits. Use an authorized admin for credential, model, quota and price management. Add encrypted API keys through AI Workspace > API Key Management: Resume Extraction slot for extraction (Responses write); OpenAI general slot for analysis, rewrite and interview review (Responses and Moderations write). Separate keys can be explicitly assigned per review feature. Test keys, then use Configure route for each feature and select approved model, primary/backup credentials, enabled status, daily quota, output token cap and member credit price where applicable. Extraction has its own configuration and existing direct provider usage accounting, not a member-credit debit. The migration does not change existing resume configurations. No key or live price is supplied by this update.

After enabling the selected review operation, use Test operation in its Workspace row. This queues a synthetic sample with the configured primary model, structured output and moderation; charges provider budget, not member credits. It does not test backup or the full user workflow. Extraction retains its existing credential test and should be tested with a non-sensitive sample CV. Confirm the actual member flow with a Pro resume test account and Plus/Pro interview account. Review real usage in the existing dashboard. Disable an operation at any time to block new requests and not-yet-executed member reviews.

## Safety and persistence
Existing encrypted credentials, requests/results, budget reservations, usage accounting, credit refunds and failover rules are reused. The interview source record is checked against authenticated ownership, consent, saved answer revision and feature entitlement. Duplicate submissions for the same unchanged answer reuse a pending/completed review. Editing clears the current review link; queued work rechecks the revision before contacting the provider. A request already at the provider when an edit happens may still complete and incur actual usage; the old review is not attached to the new answer. Definitive failures release member credits; ambiguous provider outcomes follow the existing reconciliation flow without blind retry. For the three review operations the OpenAI generation timeout is capped at 35 seconds and moderation at 8 seconds per call. No new provider SDK or worker architecture. Resume & imports remains explicitly hidden.
