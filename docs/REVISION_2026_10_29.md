# PM Circle — Prototype fidelity and temporary email-verification configuration

## Reason for change
The prior homepage omitted community preview features and used a narrower shared public container. The prior member post detail omitted guidelines, author context, threaded discussion presentation and the illustrated call-to-action. These differences were inconsistent with the supplied reference screens.

## Files changed
- `resources/css/pm-prototype.css` / `resources/css/app.css`: Desktop layout width and reference-specific public/member styling, without changing auth geometry.
- `resources/js/pages/public/Home.tsx` and `resources/js/components/home/*`: Homepage rebuilt in small components to follow screenshot sections.
- `resources/js/pages/community/PostShow.tsx`, `resources/js/components/community/CommunityComment.tsx`, `PostSidebar.tsx`, `PostCard.tsx`: Post layout, sidebar and nested discussions.
- `resources/js/layouts/pm/PublicLayout.tsx`: Optional post-page header CTA label.
- `resources/js/components/pm/Avatar.tsx` / `public/images/demo/*`: Reference-only demo portrait crops.
- `config/pm-circle.php`, `app/Models/User.php`, `app/Http/Middleware/HandleInertiaRequests.php`, `resources/js/layouts/pm/OnboardingLayout.tsx`, auth and scenario/community pages: Temporary verification toggle and accurate UI gating.
- `database/seeders/DemoCommunitySeeder.php`, `database/seeders/DatabaseSeeder.php`, `app/Http/Controllers/PublicSite/HomeController.php`: Local-only demo population of posts, replies, scenario responses and public-page previews.
- `database/migrations/2026_10_29_000002_create_comment_likes_table.php`, `app/Models/CommentLike.php`, `app/Models/Comment.php`, `app/Http/Controllers/Community/PostInteractionController.php`, `routes/web.php`, `app/Http/Controllers/Community/PostController.php`: Persisted comment likes, guarded by the current post and verified/onboarded authenticated user.
- `tests/Feature/*`: Test cases for temporary verification bypass and secure comment like routing; existing email verification tests explicitly re-enable their feature.

## Data and security
One non-destructive migration creates `comment_likes`. Demo seeding is local/testing only. No existing payments, subscription values, or private data are changed. No fake verification timestamp is set. When re-enabling mandatory verification, existing accounts with NULL `email_verified_at` must complete the verification process.

## Local testing steps
1. Install backend and frontend dependencies and set up PostgreSQL/Redis.
2. `php artisan migrate && php artisan db:seed`
3. `php artisan test`
4. `npm run types:check && npm run build`
5. Compare homepage, member-post, onboarding and mobile widths against reference images in `docs/references` at desktop and phone widths.

## Release precautions
The SRS requires verified email at launch. This temporary bypass must be removed or re-enabled before production. AI scoring and paid subscriptions remain disabled until legitimate provider integrations and verification are available.
