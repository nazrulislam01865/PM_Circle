# Admin achievements and badge management

Source: Archive 7.zip; PM_Circle_Badge_Management_Refined_Prototype.html and supplied screenshots. The current design guide specifies Inter; existing design tokens are reused without changing global typography. No other admin or member feature is redesigned.

Admin route: `/admin/achievements`. Existing active, verified admin role middleware protects all reads and mutations. The sidebar contains All badges, Task & event rewards, Award records and Member preview. Shared PMDropdown, BadgeMedal, AdminLayout, Radix dialogs, existing buttons, typography and tokens are reused. The three prototype layouts use real catalog data, not simulated counts, demo records or local storage. The preview does not award badges. Work list pagination is local (25 per page); award records are server paginated (25 per page). Badge library defaults to 10 rows.

The uploaded source previously had 42 config-only badge definitions and derived member achievements, without an admin editor or permanent award ledger. The additive migration imports the original 42 definitions, retains unsupported metrics as paused, and creates a unique member/badge ledger plus verified-work aliases. Historical prototype sample badges/counts are not imported. Existing earned snapshots are immutable after recording; revocations are permanent for that badge/member pair. Repeated award evaluation is idempotent. Badge edits use optimistic version validation; issuing an award checks current active status and version under a shared lock. Deletion is prohibited for any badge with award history. Custom artwork uses the existing public storage disk; old image files are retained because historical awards/duplicates may reference them. Use the normal storage backup procedure.

Member awards are reconciled when the existing dashboard/achievements snapshot is evaluated. Existing milestone query remains batched; a catalog query and a member ledger query are added, with an insert and locked version check only for new qualifying badges. Specific work adds one bounded query per configured source family (course completion, lesson progress, daily challenge), not per badge; generic work uses existing verified metrics. Work aliases share the same canonical source, preventing duplicate aliases from being counted twice. No background scanner, additional package, external AI call or payment changes. Event registration is not attendance; events, Scrum, project simulator, reactions and other unintegrated verification sources cannot be activated until proper evidence exists. The existing community reply count follows the prior projection; it does not distinguish comments vs replies. The preview is visual and read-only, not a simulated completion/award engine.

## Staging/release

1. Back up database/storage, deploy source to staging, install locked dependencies. Run `php artisan migrate --force` on staging and run `php artisan test --filter='AchievementManagementTest|MemberAchievementsTest'` against a test database (not production).
2. **Before allowing admins to change imported definitions**, run `php artisan achievements:record-existing --force` during a low-traffic maintenance window. This optional one-time scan materializes currently qualifying awards for existing active eligible users without duplicate rows; the old source had no immutable history and cannot recover previously lost/restricted activity. It is not scheduled. Avoid concurrent badge edits during this scan. Without it, existing awards are recorded lazily and rules changed before a member's first evaluation may change their apparent eligibility.
3. `npm ci`, `npm run types:check`, `npm run build`, `php artisan optimize:clear`, `php artisan optimize`. Ensure the public storage link exists for uploaded artwork. Compiled assets from the old upload are excluded.
4. Browser test at desktop and mobile sizes: quick create; edit; draft; pause/archive; duplicate/delete without history; attach and detach through editor; verify matching modes; upload/remove artwork; error messages; pagination; member preview; revocation. Verify direct and milestone awards for two separate users and ensure no duplicated awards. Compare screenshot spacing and run database performance checks before production.

Verification in this environment: 567 Node regression tests pass (including three new tests), PHP and TS parse checks; Laravel integration, full frontend typecheck/build, visual browser and load tests are not run because project dependencies and database drivers are unavailable. No production server or data touched.
