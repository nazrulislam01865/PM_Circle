04 · Implementation rules

  • Import the shared CSS once. Do not recreate component styles page by page.
  • Use the same spacing, field height and font tokens across registration, profile, learning, discussions and simulators.
  • Use visible labels and appropriate autocomplete attributes.
  • Required fields use * and real HTML required validation. Mark optional fields clearly.
  • Keep Tab order logical and focus visible. Never remove outlines.
  • On mobile, stack fields and keep touch targets at least 44px.
  • Use semantic HTML and announce async errors/status changes.
  • Dialogs must trap focus, close with Escape and restore focus to their trigger.
  • Do not use colour alone for selected, locked or error states.

This is a front-end specification and component demonstration. Authentication, payments, file upload, data persistence and access rules require application logic.
